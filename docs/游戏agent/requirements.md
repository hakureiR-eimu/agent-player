# 游戏 agent：需求

单个 agent 的形态：会话 + 文件夹。一个 agent 就是一个 Claude Agent SDK 会话（由运行时拉起），配上一个自己的文件夹；状态就是文件夹里的内容，动作就是读写文件夹、调用工具。

## 文件夹

一个 agent 的文件夹长这样（tag 是国家代码，如 GBR），每局一套，局与局之间不串：

```
agents/<tag>/
  profile/     开局就位，整局只读
  world/       只有运行时写，agent 只读
    chat/      飞书聊天记录
    state/     游戏状态
  memory/      只有 agent 自己写
```

### profile/

agent 的提示词和所扮演国家的介绍，开局就位、整局不变，agent 只能读：

- 通用提示词（所有国家相同）：
  - 身份：告诉 agent 它扮演的是《维多利亚3》的一名玩家。
  - 能力：告诉 agent 它可以操作游戏，可以去飞书跟其他玩家沟通。
- 国家介绍：所扮演国家的介绍（素材来自 资料/主要国家/）。

拉起会话时，系统提示词从 profile/ 组装；运行途中 agent 也可以回来翻。

### world/

agent 眼里的外部世界，都从这里读，自己不许写：

- chat/：飞书的聊天记录，大群、小群都落在这里；文件里的格式和会话里递消息的格式用同一套场景标签。
- state/：游戏状态；开局形势（开局时的国际形势）也在这里，开局时由运行时写入。

完整的聊天记录都在 chat/：新消息照常递进会话（保证被看见、能反应），同时运行时落进 chat/；翻旧账、上下文被压缩后找回记忆，都靠读这里。

### memory/

agent 唯一能写的地方，仿照一个真实的维多利亚3玩家的自我认知：

- 我的长期状态与长期目标（关于自己）：长期状态是对自己的稳定认知——家底、发展路线、在世界上的定位这类；长期目标是战略层面想达成的。两者放在一起，相对稳定，不随当前状态切换而变；由 agent 自己设定，也允许自己修正。
- 我的当前状态与短期目标（关于自己）：仿照 4X 游戏的设定，四种（探索、扩张、建设、征服）。每种状态带一个短期目标；agent 自己判断短期目标达成、失败、或出现更好的目标时切换到另一种状态，选哪种由 agent 自己决定，切换后更新短期目标。四种都从外交的角度定义：
  - 探索：获取其他 agent 的态度和观点。
  - 扩张：向非玩家的地区扩张；重点是了解可能与自己利益冲突的玩家的态度，避免引发大战。
  - 建设：获取游戏的信息，整理自己的状态（场景一没有游戏接入时，主要是整理自己的状态）。
  - 征服：准备与其他玩家开战；积极合纵连横，判断敌我关系，划分阵营。
- 我的外交状态（关于其他人）：对每个其他国家的关系、印象与立场。

文件怎么组织先不规定，玩一两局看 agent 自然记什么，再决定要不要固化格式。world/ 和 memory/ 每局从空开始。

## 会话

一个国家、一局游戏、一个会话；大群、小群不拆会话：

- 进来的消息带场景标签汇入会话（【场景】说话人：内容）。
- 回复只能走发消息工具，参数里指明发到哪个群，不会串台。
- 多个场景同时来消息，由运行时排队。

会话管此刻，chat/ 管全部。

## 动作

agent 只做决策和调用工具，工具的实现都在运行时里。它的工具就这几样：

1. 读文件：profile/、world/、memory/ 都能读（read、grep、glob）。
2. 写文件：只能在 memory/ 里写和改（write、edit，权限只放行这一处）。
3. 飞书动作：在任意群里发言，跟其他玩家（真人或 agent）交流；查看群列表和任意群的成员列表；组建群。私聊暂不纳入（飞书 bot 单聊未支持）。具体动作清单见 [飞书接入](../飞书接入/requirements.md)。
4. 游戏动作：操作游戏（空接口占位），经运行时校验后执行。游戏状态的读取不设专门工具，直接读 world/state/ 文件。见 [游戏接入](../游戏接入/requirements.md)。

一句话原则：**读走文件、写走工具**——agent 对外部世界（飞书、游戏）的一切写入都通过工具由运行时代为执行，直接动文件只发生在 memory/。
