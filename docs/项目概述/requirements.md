# 需求文档：维多利亚3 国家扮演 agent

## 一句话目标

做一个多 agent 运行时：它能拉起一个或任意个 agent，这些 agent 扮演《维多利亚3》里指定的主要国家，加入飞书群，在大群和小群里和其他玩家沟通，完成游戏里的外交决策与判断。

## 目标场景

两个场景，先做第一个。

### 场景一：飞书外交（高优先级）

- 一局游戏对应一个给定的飞书群聊，作为公屏大群。
- 所有 agent 玩家和任意数量的真人玩家都在大群里。
- agent 可以在大群发言，也可以在小群里沟通；小群从大群成员里拉人（真人或 agent 均可），用于密谈。
- 沟通只有大群和小群两种形式，不用单聊。
- 此阶段不做游戏接入：agent 不直接读写游戏，只做外交层面的沟通与决策。

### 场景二：同局游戏（低优先级）

- 运行时同时拉起多个 agent，加入同一局维多利亚3。
- 几名人类玩家和若干 agent 玩家共同游戏。
- 依赖游戏接入（见开放问题），目前只有目标，没有方案。

## 系统组成

整个系统由两部分组成：一个多 agent 运行时，和它拉起的若干 agent。两者的详细需求分别见 [多agent运行时/requirements](../多agent运行时/requirements.md) 和 [游戏agent/requirements](../游戏agent/requirements.md)。

### 命名

定名"多 agent 运行时"（曾拟名"基座"）。它做的事情：拉起 agent、提供沙箱并初始化、把它们接到飞书和游戏上。下文简称"运行时"。

### 运行时的职责

1. 拉起 agent：运行时启动时带起一个网页控制台，游戏开始前在网页上选择国家、手动拉起一个或任意个（预期少量）agent；每个 agent 是一个 Claude Agent SDK 的 session，扮演指定的一个主要国家。
2. 提供目录并初始化：不做沙箱；一局游戏一个局文件夹，下设不可变文件夹（放所有 agent 的不可变状态）和各国自己的文件夹（放可变内容）。
3. 接入飞书（高优先级）：把每个 agent 接进给定的大群，让它们能收发大群消息、能进小群沟通。具体怎么做见飞书接入文档。
4. 绑定游戏进程（低优先级）：为 agent 提供 readGame / writeGame 两个接口（见"游戏动作"）。受游戏本身运行方式的限制，怎么读写完全没想好，先做空接口占位，暂缓实现。见游戏接入文档。

### 单个 agent 的形态：状态 + 动作

#### 状态

分两类。

**不可变状态（薄，运行时提供）**

- 初始化时由运行时写入（放局根文件夹下），agent 运行期间只读、不能改。
- 通用部分（所有 agent 相同）：
  - 身份：告诉 agent 它扮演的是《维多利亚3》的一名玩家。
  - 能力：告诉 agent 它可以操作游戏，可以去飞书跟其他玩家沟通。
  - 开局形势：游戏开局时的国际形势。
- 国家特有部分：所扮演国家的介绍。
- "薄"的意思是只放必要的东西，不堆大段资料。

**可变状态（agent 自己维护）**

放在自己国家的子文件夹里，agent 自己读写。仿照一个真实的维多利亚3玩家会有的自我认知：

- 我的目标：agent 想达成的战略目标。
- 我的当前状态（关于自己）：仿照 4X 游戏的设定，设四种当前状态（暂拟：探索、扩张、开发、征服）。agent 自己判断并切换当前状态；基于当前状态，agent 要进行不同的操作（每种状态对应的操作细则待补，见开放问题）。
- 我的外交状态（关于其他人）：对每个其他国家的关系、印象与立场。

#### 动作

分三块。

1. 文件动作：读写自己文件夹内的文件，由 Claude Agent SDK 提供——用 grep 搜索内容，用 read、write、edit 读取和编辑。可变状态就存这些文件里。
2. 飞书动作：在大群和小群里发消息，用于和其他玩家（真人或 agent）交流。具体动作清单见飞书接入文档。
3. 游戏动作：先立两个空接口函数，未来再填实现——readGame 起到读游戏状态的作用，writeGame 起到操作游戏状态的作用。

## 优先级总览

| 能力 | 优先级 | 说明 |
|---|---|---|
| 运行时拉起 agent、建目录、初始化 | 高 | 一切的前提 |
| 飞书接入 | 高 | 场景一的本体 |
| 文件动作 | 高 | agent 维护自身状态的唯一手段 |
| 飞书动作 | 高 | agent 对外的嘴 |
| 游戏接入（readGame/writeGame 实现） | 低 | 接口形状已定，实现暂缓 |
