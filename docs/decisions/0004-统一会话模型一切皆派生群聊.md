# 决策 0004：统一会话模型——一切会话皆从公屏群派生

- **日期**：2026-10-12
- **状态**：已采纳（作者提出并拍板）

## 背景

决策 0003 确立"所有通信走飞书"后，面临会话形态问题：公屏/私聊/集团三种通道是否各自实现？以及遗留的"bot 与 bot 能否直接私聊"待验证问题。

## 决策

**所有外交会话统一建模为"群"（chat），构成以全员公屏群为根的派生体系：**

- **全员公屏群 = 根**：开局创建，玩家 + 所有列强 agent 都在，公开外交发生地
- **双边会话 = 2 人群**：玩家×某国（"私聊"）、某国×某国（agent 密谈）
- **集团会话 = 多国子群**：联盟内部协调、多方密约
- 一切子群从公屏群**派生**；公屏群自身作为根节点纳入同一会话模型管理

## 理由

1. **单一会话原语**：agent 只会一种通信动作——"往某会话发消息"。公屏/私聊/集团只是成员集合不同的会话类型，代码与 prompt 结构统一，无特判分支。
2. **化解 0003 的 bot-bot 私聊依赖**：私聊即 2 人群，根本不存在 bot-bot p2p 通道依赖。若飞书 2 人群体验与私聊无实质差别（群名即对方国名），沉浸感不打折。
3. **信息不对称 = 群成员制**：可见性即成员资格，与决策 0003 的精神同源，且由飞书权限模型天然保证。
4. **外交叙事素材**：群的创建与解散本身就是外交事件——"英俄建立秘密渠道""三国集团成立"。派生关系构成整局比赛的**会话图谱**，复盘、直播、对局分析都可讲。
5. **拟真**：对应真实国际会议体系——大会（公屏）+ 委员会/密室（派生小会）。

## 后果

- **开局流程**：创建全员公屏群 + **预建"玩家×每国"双边群**（玩家开局即有"联系人列表"可点开，发现性最好）；国×国双边群、集团群按外交进程**按需派生**。
- **群生命周期成为外交工具集**：建群、拉群、退群、解散都是 agent 可执行的外交动作（受白名单约束，同"规则层高于语言层"原则）。
- **待验证（飞书）**：bot 建群、bot 把另一个 bot 拉入群、单应用建群数量上限、2 人群的收发语义。
- **开放细节**：同一对国家的双边会话是否唯一（第一版建议唯一，重建=特殊外交事件，暂不开放）。

## 被否决的方案

- **混合形态**（公屏用群、私聊用 p2p、bot-bot 再特判）：三套消息逻辑，p2p 对 bot 不通用，复杂度白白翻倍。
