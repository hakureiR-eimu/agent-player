# 决策 0001：飞书多国身份采用"一国一应用"

- **日期**：2026-10-12
- **状态**：已采纳（作者拍板）

## 背景

飞书中一个自建应用 = 一个机器人身份（一个名字一个头像）。要让英法俄普奥等列强各自以独立身份出面，有三个候选：

| 方案 | 做法 | 主要代价 |
|------|------|---------|
| **A. 一国一应用** | 建约 8 个自建应用，各自收发消息 | 应用管理、token、事件订阅 ×8，工程量最大 |
| B. 单应用 + 卡片署名 | 一个 bot 转达所有国家发言，卡片标注"[普鲁士]" | 出戏；私聊（秘密外交）形态不成立 |
| C. 混合 | 私聊一国一应用，公屏单应用转达 | 折中，公屏仍出戏 |

## 决策

**MVP 直接采用方案 A：每个列强一个飞书自建应用。**

## 理由

1. **沉浸感是产品本体**：本项目的核心体验是"像和真人联机谈判"。转达/署名式发言的出戏不是小瑕疵，而是破坏价值主张——尤其私聊通道：秘密外交要求对面真的是"普鲁士王国"这个机器人身份。
2. **动态列强是既定方向**：远期将按列强榜涨落动态创建/销毁 agent，飞书应用的创建、配置、退役是长期必备能力。方案 A 的管理成本是必要投资，不存在"先 B 省事、后升级 A"的省钱空间——B 的转达架构到时候只会被推倒重写。
3. **成本可控**：8 个应用的创建与配置可以脚本自动化，属一次性工程投入，边际成本低。

## 后果

- 需要一个应用批量创建/配置/凭证管理的自动化脚本（成为基础设施的一部分）
- 事件订阅、token 刷新 ×8 需要统一的管理层（不能手工维护）
- 该管理层同时服务未来的"动态列强接入"（见 brainstorm）

## 被否决的方案

- **B**：出戏破坏"类人联机"核心体验；秘密外交形态不成立。
- **C**：仍是妥协——公屏同样需要各国以独立身份发言表态，半吊子方案没有存活空间。
