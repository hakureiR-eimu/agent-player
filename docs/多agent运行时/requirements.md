# 多 agent 运行时：需求

## 职责

1. 启动并拉起网站：运行时启动时就带起一个网站（网页控制台）。开局、拉起 agent 都在网页上操作。
2. 开局命名：给本局游戏起名。局名一身四用：这场游戏的名目、局文件夹名、公屏大群群名、DM 的名字。
3. 创建公屏大群：由 DM 应用以局名建群，DM 当群主。DM 是非 LLM 的飞书 bot，名字就是局名。具体见 [飞书接入](../飞书接入/requirements.md)。
4. 拉起 agent：在网页上点"拉起 agent"，选择要拉起哪些国家；每个 agent 是一个 Claude Agent SDK 的 session（同一个进程里的多个会话，不是独立进程），一个 session 扮演一个指定的主要国家。
5. 建目录并初始化：命名时建局文件夹；拉起时为每个选中的国家建 agents/<tag>/，装好 profile/，建好 world/ 和 memory/（结构见下）。
6. 接入飞书：玩家（真人或 agent）都由 DM 拉进大群；小群由玩家发起、DM 代建并拉人。具体实现见 [飞书接入](../飞书接入/requirements.md)。
7. 绑定游戏进程：放在开局流程最后。每个 agent 绑一个游戏进程（一国一进程），进程人工开好，在网页上与国家配对；为 agent 提供 readGame / writeGame 两个接口，先做空实现。具体见 [游戏接入](../游戏接入/requirements.md)。
8. 实现所有工具：agent 只做决策和调用工具；飞书收发、readGame/writeGame 等工具的实现都在运行时里。

优先级：6（接飞书）高，7（接游戏）低。

## 目录结构

一局游戏一个局文件夹，多级结构：

```
局名/                  ← 表示这场游戏，文件夹名就是局名
  agents/
    GBR/               ← 一国一个文件夹，该国 agent 的全部内容都在这
      profile/         开局就位，整局只读
      world/           只有运行时写，agent 只读
        chat/          飞书聊天记录
        state/         游戏状态，开局形势开局时写入
      memory/          只有 agent 自己写
    FRA/
    ...
```

三区各放什么、谁读谁写，见 [游戏agent](../游戏agent/requirements.md)。

## 开局流程

1. 启动运行时，运行时拉起网站。
2. 在网页上给本局游戏命名；运行时以局名建局文件夹；人工把 DM 的名字改成局名（飞书没有改应用名的 API），运行时用 DM 以局名创建公屏大群。
3. 在网页上点"拉起 agent"，勾选要拉起的国家。
4. 为每个选中的国家建 agents/<tag>/：装好 profile/（通用提示词、国家介绍），把开局形势写进 world/state/，建好空的 world/chat/ 和 memory/。
5. 拉起 agent：创建会话，提供初始上下文；DM 把各国应用拉进大群。
6. 沟通阶段：玩家在大群里互相沟通，做游戏操作以外的事。
7. 游戏开始前：人工开好游戏进程，在网页上把进程与国家配对，绑定。

## 生命周期

- 开局：在网站上手动拉起。
- 一局结束：手动结束。
- 中途出问题：session 报错，重新拉起该 session 即可。

## 不可变内容的准备

- 内容由 Claude 写，用户审核定稿。
- 国家资料存放在 `资料/主要国家/` 下，以维多利亚3的国家 tag 作为文件夹名（如 `资料/主要国家/GBR/`），tag 是国家、文件夹、agent 的统一绑定标识。
- 开局前备好；拉起 agent 时从中取用，写入各国 agent 的 profile/。主要国家名单与 tag 对照见 `资料/主要国家/README.md`。

## 迭代计划

- 第一版：不可变内容只做开局主要国家。
- 接下来：支持一局进行中动态接入 agent、销毁 agent。

## 要回答的问题

1. 网站的形态：本地 web 服务就够，还是要能远程访问；要不要顺带展示 agent 的运行状态。
2. DM 改名的实际流程：后台改名是否必须发版、要不要管理员批准、生效多快；一局改一次的麻烦是否可接受。
