# 项目需求

## 一句话目标

做一个多 agent 运行时：它能拉起一个或任意个 agent，这些 agent 扮演《维多利亚3》里指定的主要国家，加入飞书群，在大群和小群里和其他玩家沟通，完成游戏里的外交决策与判断。

## 目标场景

### 场景一：飞书外交（高优先级）

- 一局游戏对应一个给定的飞书群聊，作为公屏大群。
- 所有 agent 玩家和任意数量的真人玩家都在大群里。
- agent 可以在大群发言，也可以在小群里沟通；小群从大群成员里拉人（真人或 agent 均可），用于密谈。
- 沟通只有大群和小群两种形式，不用单聊。
- 此阶段不做游戏接入：agent 不直接读写游戏，只做外交层面的沟通与决策。

### 场景二：同局游戏（低优先级）

- 运行时同时拉起多个 agent，加入同一局维多利亚3。
- 几名人类玩家和若干 agent 玩家共同游戏。
- 依赖游戏接入。

## 系统组成

整个系统由两部分组成：一个多 agent 运行时，和它拉起的若干 agent。

### 命名

定名"多 agent 运行时"（曾拟名"基座"）。它做的事情：拉起 agent、建目录初始化、把它们接到飞书和游戏上。下文简称"运行时"。

### 运行时的职责

1. 拉起 agent：运行时启动时带起一个网页控制台，游戏开始前在网页上选择国家、手动拉起一个或任意个（预期少量）agent；每个 agent 是一个 Claude Agent SDK 会话，扮演指定的一个主要国家。
2. 建局建目录：为每个参战国家建一套 agent 文件夹（profile / world / memory 三区），profile 从资料库（`资料/主要国家/`）取用。
3. 接入飞书（高优先级）：把每个 agent 接进给定的大群，让它们能收发大群消息、能进小群沟通。见 [飞书接入](飞书接入/requirements.md)。
4. 绑定游戏进程（低优先级）：为 agent 提供操作游戏的占位工具，实现暂缓。游戏状态的读取不设专门接口，agent 直接读自己文件夹 world/state/ 下的文件。见 [游戏接入](游戏接入/requirements.md)。
5. 实现所有工具：agent 只做决策和调用工具；飞书收发、游戏操作等工具的实现都在运行时里。

### agent 的形态

一个 agent = 一个会话 + 一个文件夹。状态就是文件夹里的内容（profile 整局只读、world 只读、memory 只有自己写），动作就是读写文件夹、调用运行时给的工具；对外部世界的一切写入都走工具。细节见 [游戏agent](游戏agent/requirements.md)。

## 优先级总览

| 能力 | 优先级 | 说明 |
|---|---|---|
| 运行时拉起 agent、建目录、初始化 | 高 | 一切的前提 |
| 飞书接入 | 高 | 场景一的本体 |
| 文件动作 | 高 | agent 维护自身状态的唯一手段 |
| 飞书动作 | 高 | agent 对外的嘴 |
| 游戏接入（游戏操作工具的实现） | 低 | 接口形状已定，实现暂缓 |
