# 游戏接入：需求与调研

## 进程形态（已定）

- 每个游戏进程对应一个玩家：一个 agent 国家绑一个维多利亚3进程，联机形态。
- 游戏进程人工开好，运行时不负责拉起游戏；绑定就是在网页上把进程与国家配对。
- 绑定放在开局流程的最后：建群、拉起 agent、入群之后，玩家先在群里沟通，游戏开始前才绑定。
- 一国一进程的附带好处：进程只能操作自己国家，agent 误碰别国被物理隔开，运行时只校验指令本身。

## 接口形状（已定）

- readGame：读游戏状态。空接口，未来实现。
- writeGame：操作游戏状态。空接口，未来实现。

## 要回答的问题

1. 在游戏 runtime 的限制下，能不能从外部读写维多利亚3的进程。
2. readGame 能读什么：国家状态、世界局势。
3. writeGame 能写什么：指令、存档。
4. 绑定时怎么标识一个游戏进程：网页上配对时看什么（进程列表、窗口标题），怎么确认它对应哪个国家。
5. 联机的账：每个进程一个 Paradox 账号；host 进程归哪国。
