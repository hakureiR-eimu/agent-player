# 决策 0005：角色方案简化为预生成 prompt + 工具化技能 + 自生成目标

- **日期**：2026-10-12
- **状态**：已采纳（作者拍板）

## 背景

早前初判（《参考/基础设施-agent与角色书.md》）：以 SillyTavern character_book 为蓝本定义"国家角色书" schema——固定人设 + 关键词触发条目（keys → content）+ 插入顺序 / 扫描深度 / 上下文预算，再扩展 V3 特有字段。作者判定**过分复杂**：本项目只是引用"角色书"的概念，不需要它的全部机制。

## 决策

对 agent 的需求简化为四层（详见 `docs/rdr/agent需求.md`）：

1. **身份不可改**：开局前预生成角色 prompt（身份 + 历史背景），运行期只读
2. **能力工具化**：飞书沟通 / 拉群 / 国家名录 / 读状态 / 白名单操作，以 skill/MCP 式"技能说明 + 工具接口"授予
3. **目标自生成可改**：agent 开局为自己生成国家目标，允许低频编辑（重大局势变化时校准）
4. **表现不出戏**：飞书言行遵守 OOC 禁止清单

## 理由

- **复杂度与收益不匹配**：keys 触发、扫描深度等机制服务于超长对话的角色扮演前端；本项目每国上下文规模可控，用不上
- **目标自生成优于手写**：目标是自己定的才有主体性；低频编辑在战略一致性与时局适应之间取平衡
- **工具化能力可插拔**：后续迭代新增操作不动 agent 内核

## 后果

- mvp.md 中"手写角色书 + 国家目标"的口径按此调整（mvp.md 本身不回写，见其固定约定；差异记录在 rdr 文档）
- character_book 降级为灵感来源；若未来上下文膨胀确需条件注入，可再评估引入
- 新增一个生产环节：角色 prompt 的预生成（方式待定，见 rdr 待定问题）

## 被否决的方案

- **SillyTavern character_book 全套 schema 作为蓝本**：过分复杂，本项目只需要概念不需要机制
