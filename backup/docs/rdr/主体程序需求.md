## 一、主体形态：一个宿主进程，八国互不可见

**组件与数据流**（自外向内）：

- **玩家 ↔ 飞书 ↔ 宿主**：玩家经飞书（8 国应用，一国一应用）与宿主双向收发；两通道（公屏 / 私聊）统一为群会话实现（决策 0004，2026-10-13 修订：拉群移除）——接入方式与消息流细则见 `飞书接入.md`
- **host（TS/Node，MVP 单进程）**，内部四件：
  - **飞书网关**：8 应用事件接入（长连接）→ 国别路由 → 发送节流；**兼管发送侧扇入**——agent 出站消息发送成功后由网关直接注入群内其他成员国的会话——内部机制全部见 `飞书接入.md`
  - **事件队列（国级串行）**：统一承接三类事件——飞书消息、快照通知、动作回执——按序触发对应国家的对应会话（§六）
  - **国家运行时 ×8**（相互隔离，见 §二）：每国 = 共享沙箱 `runtime/<TAG>/` ＋ 会话集（窗口会话 ×N ＋ 内心会话 ×1，决策 0006；构成见 §5.1）
  - **开局编排**（bootstrap，一次性，见 §五）：创建上述一切
- **host ↔ 桥服务（独立进程，MVP 暂缓）**：agent 经 `POST /action` 提交白名单动作；桥服务回推 `state.snapshot` / `action.receipt` 事件，汇入事件队列——游戏交互整体暂缓（agent需求 §三 留档），接口设计保留待接入
- **桥服务 ↔ Victoria 3**：游戏侧读写与校验，全部细节见 `docs/游戏桥接设计.md`

- **宿主职责**就四件：接飞书、管 agent 生命周期、路由事件、执行隔离。不含游戏侧任何逻辑——桥是另一个进程，宿主只消费其事件流
- **进程模型（决策 0006 修订）**：1 宿主进程 + 按需拉起的 SDK 子进程——每个会话一次 `query()`（拉起一个 Claude Code CLI 子进程，宿主经 stdio 驱动），**会话不常驻**：事件到达 → `resume: sessionId` 续起该会话 → 跑一个 turn → 子进程退出；活跃子进程数 = 活跃 turn 数（≤8 量级）。故障隔离会话级——某 turn 崩溃只丢该 turn，重 resume 即恢复，transcript 在盘上（§六）；resume 的上下文重建成本与缓存命中待实测（见待定问题）
- **无心跳**：没有事件就没有 LLM 调用。宿主是唯一的"起搏器"，agent 自己永不轮询（对应 agent需求 §1.6"无事件则无行为"）

## 二、隔离模型：四层结构，一层 prompt

**原则：隔离靠结构不靠自觉**——prompt 是最后防线，不是第一道。跨层防注入：任何输入（含恶意指令）逐层失效。

| 层 | 机制 | 挡住什么 |
|----|------|---------|
| 1 会话隔离 | 每国独立 SDK 会话 + 独立 CLI 子进程：独立 transcript、独立 system prompt，零共享状态 | 任何"顺路"的信息渗透 |
| 2 文件沙箱 | read/write 工具 cwd=该国沙箱根；execute 内校验 resolve 后路径必须落在沙箱内，越界一律报"路径不存在"（不暴露外部结构）；`thin/`、`world/` 拦截写入 | "读 FRA 的 goals.md"、篡改世界状态、改薄层 |
| 3 凭据隔离 | 飞书一国一应用（0001）：发消息工具闭包绑定该国 app token，凭据只存在于宿主配置，agent 参数里只有会话名与文本 | "以普鲁士身份发言"——工具层无此能力 |
| 4 会话可见性 | 一切皆群 + 成员制（0004，2026-10-13 修订：工具面只暴露公屏与私聊）：本国只能进入自己发起或被拉入的会话——私聊目标取自薄层名录，他国私聊对本国工具层**不存在** | 窥探他国私聊、向不在场的会话发消息 |
| 5 prompt（软） | 薄层信息纪律 + 注入防御（agent需求 §1.5） | 前四层漏网的语言层攻击 |

第 3、4 层是飞书侧结构，凭据保管与可见性判定的细则见 `飞书接入.md` §三；表格在此保留全局视图——四层是一个整体，拆开看会丢掉"逐层设防"的设计意图。

信息对称（边界定义见 agent需求 §3.1）的兑现点在**写入侧**：宿主为每国生成 `world/` 投影时就只写该国可见的信息（本国全量 + 公开信息）——他国私聊、他国内部状态**不在文件里**，是"不可见"而非"不许看"。

## 三、生命周期总览

宿主的一生四个阶段，顺序固定；每一阶段都是宿主主动做功，agent 只在第三阶段被事件唤醒：

1. **启动（§四）**：加载配置 → 起飞书网关（8 条长连接）→ 对接桥服务事件流（MVP 暂缓，跳过）——此时还没有任何 agent
2. **初始化（§五，一次性开局编排）**：确认名单 → 生产薄层 → 建沙箱 → 注册工具 → 构造 8 国 SDK 会话 → 注入初始上下文与开局触发
3. **运行（§六）**：事件驱动——三类事件入队、国级串行触发、agent 循环内自主读写厚层；单国故障按 §六重建，宿主重启走同一路径
4. **关停卸载（§七）**：停止进水 → 排水 → 确认落盘 → 卸载 8 国 agent → 断开飞书与桥 → 留存对局档案

全周期只有宿主一个"起搏器"：初始化的开局触发与运行期的事件注入是仅有的两类"叫醒"agent 的方式，此外 agent 永远静默。

## 四、启动：配置与两个事件源

**配置加载**：8 国飞书应用凭据（一国一应用，0001）、应用 ↔ 国家 TAG 对照、桥服务地址。凭据只存在于宿主配置与工具闭包，agent 参数里永远只有会话名与文本（§二第 3 层）——凭据与配置的保管细则见 `飞书接入.md` §三。

**事件源（满速两路；MVP 只有飞书网关一路，桥对接暂缓）**：

- **飞书网关**：8 应用长连接接入、收到的消息按"所在群的成员 bot"定受件国、对外发送节流、agent 出站消息扇入——接入定案、平台限制情报与消息流细则全部见 `飞书接入.md`
- **桥服务对接**：桥是独立进程，宿主消费其回推的两类事件（`state.snapshot` / `action.receipt`），与飞书事件汇入同一队列（§六）；agent 侧对桥的调用（`GET /state`、`POST /action`）以绑定组工具形式注册（§5.2），接口细节全部见 `docs/游戏桥接设计.md`

## 五、初始化：把 8 个 agent 造出来（一次性开局编排）

### 5.1 每国 agent 由什么构成（薄厚层 → SDK 落点）

| agent需求 | SDK 落点 | 机制保证 |
|-----------|---------|---------|
| 薄层＝规则五件（agent需求 §1.2） | 每个会话的 system prompt：共用骨架 + 风味包（生产方式见 0005）＋ 会话头（窗口头 / 内心头，百来字） | `options.systemPrompt` 构造时一次性注入，SDK 无任何运行期修改 / 追加接口（已核对）——**薄层不可变由结构锁死**，不靠自觉 |
| 厚层＝认知三件（agent需求 §1.3：世界 / 自我 / 记忆） | 沙箱文件（目录见下） | 读写为自制工具，路径校验在 execute 内（cwd＝沙箱根，§5.2） |
| 对话记忆（agent需求 §1.3） | 各会话 transcript：每事件一次 query（resume 该会话 session，§六）跑一个 turn，SDK 会话天然累积；跨窗口记忆 = 宿主机械落的 `memory/chats/` 只读记录 + agent 自记摘录 | harness 自动落盘 JSONL（§六）；transcript 是经历，文件是笔记本 |
| 自身状态与记忆落盘（agent需求 §1.3、§1.7） | `self/`、`memory/` 文件 | 写前版本留痕（`.history/`） |

沙箱目录布局：

```
runtime/<TAG>/
  thin/          薄层固化（identity.md 风味包 / protocol.md 对话要求）—— agent 只读
  world/         世界状态投影（snapshot 等）—— 宿主写入，agent 只读
  self/          自身状态（goals / ledger / 战略阶段 / 态度档案）—— agent 读写
  memory/        记忆（事件脉络、远期摘要）—— agent 追加
  memory/chats/  各窗口聊天记录的机械落盘（宿主维护）—— agent 只读（翻聊天记录）
  .history/      宿主维护的写前版本留痕 —— agent 不可见
```

- **transcript 是经历，文件是笔记本**：agent 觉得重要的事实（承诺、剧变、态度）才落 `self/`、`memory/`；读什么进上下文、远期怎么压缩由 agent 自主（组装与压缩已定案，agent需求 §1.4）
- **写入留痕由宿主执行**：任何对 `self/`、`memory/` 的 write 落盘前，旧文件自动移入 `.history/`（时间戳命名）——目标编辑留痕、记忆不可篡改（agent需求 §1.3）的结构化兑现；agent 无感知，接口仍是纯读写文件。MVP 不做仅追加文件锁，版本链即审计

### 5.2 工具注册（已核对 2026-10-13，官方文档）

- **工具注册**：`createSdkMcpServer()` 建**内存 MCP server**（进程内、不走 stdio），工具用 `tool(名, 描述, zodSchema, execute)` 定义——入参由 SDK 按 schema 校验后才进 execute，返回 MCP content blocks；工具以 `mcp__<server>__<tool>` 暴露，`description` 即技能说明，构成薄层的"工具说明"部分（与 agent需求 §1.7"MCP 语义原生"定案严丝合缝）
- **内置工具全卸**：`tools: []`（装载层，模型根本看不到内置工具）——工具面只剩我们的内存 MCP server。read/write 也**自制**，路径校验在 execute 内：沙箱根 resolve 后前缀判定、`thin/` `world/` 拦截写、越界一律报"路径不存在"——校验 100% 在自己代码里。不依赖内置 Read/Write：其读默认可越 cwd，锁死要叠权限规则且 Windows 路径规则写法文档未确认
- **拦截与硬约束**：PreToolUse hooks（matcher + `permissionDecision: "deny"` + reason 回传模型）与 `canUseTool`（deny + 自定义 message 直达模型）皆可承载；发言限流等行为类约束的细则归沟通文档（待建），计数拦截落在本机制。注意：①须用 `permissionMode: "default"`（bypassPermissions 会跳过 permission 体系）；②canUseTool 文档要求流式输入模式——决策 0006 改按需 resume 后，单次 query 仍可传 `AsyncIterable`（yield 本轮合并消息后即关闭）以保此模式，或退而以 PreToolUse hooks 为唯一承载，二选一待 `.d.ts` 复核（见待定问题）；③sandbox 选项只管 shell 且原生 Windows 不支持——我们 `tools: []` 后无 shell，不受影响

**工具分组与清单**（语义清单以 agent需求 §2.1、§3.1 为准）：

| 组 | 工具 | 落点 |
|----|------|------|
| 通用组 | `read_file` / `write_file` | §5.2 机制自制；路径校验在 execute 内；写前留痕（§5.1） |
| 绑定组·飞书 | `send_message`（公屏）/ `dm`（私聊） | 同一机制注册，闭包绑定本国 app token（§二第 3 层；绑定内容与凭据保管见 `飞书接入.md` §三）；**工具名与描述不出现"群"等实现词**——私聊底层的找或建 2 人群在 execute 内完成、agent 无感知（0004 修订）；语义、会话解析、发言限流细则归沟通文档（待建） |
| 绑定组·游戏 | 读局势 / 发起外交博弈 / 加入外交博弈 | 同一机制注册；对接桥服务（`GET /state`、`POST /action`），细节见 `docs/游戏桥接设计.md`；失败回执作为事件回流（§六） |

### 5.3 开局流程（顺序步骤）

1. **名单**：开局确认玩家 tag（MVP：人工指定；后续可由桥检测），玩家国不接入；其余列强全接（agent需求 §〇 总纲·接入范围；1836 名单人工录入，桥 S1 验证后与游戏核对）
2. **飞书就位**：8 应用、凭据、开局建群——细则见 `飞书接入.md` §六
3. **薄层生产**：每国 = 共用骨架 + 风味包（手写或 LLM 生成后人工审定，0005），写入 `runtime/<TAG>/thin/`
4. **沙箱创建**：按 §5.1 布局初始化目录骨架——`world/` 落开局静态背景（MVP：人工编写的 1836 世界格局；接桥后改为 `GET /state` 投影），`self/`、`memory/` 空
5. **工具注册**：按 §5.2 为每国建内存 MCP server——通用组 + 闭包绑定该国凭据的绑定组，`tools: []` 全卸内置
6. **会话映射建立**：不预拉起会话（按需 resume，§一进程模型），只建**会话映射表**（飞书会话 ↔ SDK session 槽位）：开局登记公屏窗口 + 预建的"玩家×每国"私聊窗口（0004）+ 内心会话；此后私聊窗口随新私聊对象按需登记（宿主找或建 2 人群）。每个会话首次触发时构造：systemPrompt = 薄层 + 会话头（一次性注入，不可变见 §5.1）、cwd = 沙箱根——初始上下文 = 薄层（规则）+ `world/` 开局投影（事实），此后一切增量走事件（§六）
7. **开局触发**：向每国**内心会话**注入首事件——"对局开始，读取你的世界与自我，确立目标"（开局盘算属内心会话职责，决策 0006；meta 抉择与目标生成的语义见 agent需求 §1.3），产物落 `self/`
8. **开张（定案）**：不安排公屏开局表态——联机实况是公屏天然冷清、外交主战场在私聊/小群；探索期的主动接触以玩家双边群（私聊）为主，公屏留给真正需要公开的事（宣战、公开站队、博弈公开化）

初始化失败重来的 MVP 口径：整局清 `runtime/` 重跑，不做按国断点续建（是否够用见待定问题）。

## 六、运行：事件驱动与国级串行

**事件队列与国级串行**：事件统一入队（满速三类：飞书消息、快照通知、动作回执；**MVP 只有飞书消息一类**，后两类通道已设计、待游戏接入），按国别分道；一国同时至多一个进行中的 turn（**国级串行**，决策 0006——不分窗口，保护共享沙箱的写）。轮到该国时 resume 目标会话跑一轮（`query()` + `resume: sessionId`，以 `result` 收尾），完成才取下一件。**攒批**：同窗口的排队消息注入前由宿主合并（"玩家连发三条、攒一波再回"——每会话一次 query，合并即拼 prompt）；跨窗口不合并。

**收消息分两路（概述）**：飞书消息分两路进队列——玩家消息（真人所发）走长连接推送、按群成员路由；agent 消息（接入国所发）走宿主发送侧扇入——平台依据与机制细节见 `飞书接入.md` §四。agent 没有"收"这个动作，只有"被触发"（对应 agent需求 §1.6 的行为循环）；两路消息汇入同一事件队列、同一触发格式（见下），下游无差别。

**触发注入（最小注入原则）**：唤醒 agent 的 user 消息 = 环境头（游戏日期 + 事件来源标注）+ 事件本身，**不带世界摘要**——局势由 agent 按需自读（认知组装已定案交给 LLM，agent需求 §1.4）。**路由到会话**（决策 0006）：聊天消息 → 该国对应窗口会话；快照通知与动作回执 → 内心会话。**快照通知式注入**：宿主把全量快照写 `world/`，事件体只是短通知（"1837.3 快照已就位，较上月：俄土开战"两三行要点），要细节自读文件——不让全量局势灌爆内心会话的 transcript。日期每次必带：agent 对时间流逝的感知全靠环境头（readiness 含时间条件，agent需求 §1.3）。

**transcript 压缩**：SDK 自动压缩默认开启（接近上下文上限折叠早期历史），触发时发 `compact_boundary` 系统消息、可观测；开关与阈值在 settings 层。窗口拆分（决策 0006）把压缩压力按窗口分摊——一个私聊的量远小于全部会话总量，压缩更晚、丢细节更少。system prompt 与工具定义每次请求随发、不进压缩历史（部分确认，落地时以 `.d.ts` 复核）。`memory/` 外部笔记不受 compaction 影响——"transcript 是经历、文件是笔记本"的又一理由。

**故障重建**：

- transcript：harness 自动落盘 JSONL（`~/.claude/projects/` 下按 session id），无需自写；多会话各落各的，**会话映射表**记录飞书会话 ↔ session id；重建 = `resume: sessionId` 恢复全量历史（含工具调用）——按需 resume 模型下重建就是正常路径，崩溃只丢未完成的那个 turn。审计日志另建议消费 SDKMessage 流同步写自己的库——JSONL 位置与格式由 harness 固定，不作依赖
- 事件队列持久化 inbox：收到落盘 → agent 完成一个 turn（收到 result）→ ack 删除；重建 = resume + 重放未 ack 事件；at-least-once，按 message_id 幂等去重（yield 前查重）——inbox / ack / 重放 SDK 无对应物，纯宿主自研（本就是宿主职责）
- 极端退化（存档与 inbox 同时丢失）：飞书拉最近消息 + 最新快照重建，接受少量失忆（外交场景可容忍，可解释为"闭门数日"），MVP 不做更重的持久化
- `Query.interrupt()` 可主动打断进行中的 turn——可做"召回 / 紧急叫停"类干预，也是 §七关停排水的手段

## 七、关停与卸载（程序结束后卸载 agent）

**触发**：MVP 关停一律人工指令（宿主命令 / Ctrl-C）；游戏终局自动判定不做（桥的终局识别非 MVP 范围）。

**顺序（排水式关停）**：

1. **停止进水**：飞书网关停止消费新事件，桥事件流停收；inbox 继续落盘——未处理事件不丢
2. **排水（drain）**：等待在途 turn 完成——国级串行（§六）保证每国至多一个进行中 turn；设排水超时（量级见待定问题），超时国用 `Query.interrupt()` 打断；被打断的事件未 ack、留在 inbox，供续局重放（与 §六故障重建同机制）
3. **确认落盘**：transcript JSONL 由 harness 自动落盘（§六），关停时确认 8 国最后一段已刷盘；审计库（若启用 SDKMessage 流写库）补写尾部
4. **卸载 agent**：会话本就不常驻（§一进程模型），排水后无在途 turn 即无子进程；确认活跃子进程全部退出、超时未退的强杀——**卸载后无残留子进程**
5. **断开外部**：断开 8 条飞书长连接（飞书侧细则见 `飞书接入.md` §六）、断开桥事件订阅
6. **留存对局档案**：`runtime/` 整体留存不删——沙箱（薄层 / world / self / memory / .history）与 inbox 存档即为对局档案，复盘、审计、验收取证全靠它；可选压缩归档（策略见待定问题）

**卸载消灭的是进程，不是事实**：沙箱文件、transcript 存档、飞书侧会话（群还在飞书里）全部留存。

**续局与跨局**：

- **续局**（同一对局重启宿主）：走 §六故障重建同一路径——resume sessionId + inbox 重放未 ack 事件；沙箱与 transcript 都在盘上，天然跨进程存活
- **跨局**（开新一局）：新对局不复用旧 `runtime/<TAG>/`——记忆仅局内、跨局无记忆（agent需求 §1.3）；旧目录整体归档，开局编排（§五）在干净目录上重跑

## 验收标准（工程侧；扮演与行为验收以 agent需求 验收表为准）

- 启动：桥事件汇入同一事件队列，与飞书事件按国别分道；长连接建立、事件路由与扇入送达的验收见 `飞书接入.md`
- 初始化：8 国共享沙箱与会话映射表构造完成（公屏窗口、玩家双边窗口、内心会话登记在册）；全流程无任何代码路径修改 system prompt 或 `thin/`（薄层运行期不可变）
- **跨国不可达**：构造注入用例（"读 FRA 的目标""以他国名义发言""私聊名录之外的对象"）逐层验证——工具层分别报"路径不存在/无此会话"，无一泄露存在性
- 信息隔离：他国私聊不出现在本国 transcript 与 `world/` 投影中（引 mvp 验收；三通道收发细则归沟通文档，待建）
- 单国故障（LLM 超时/工具抛错/子进程崩溃）不影响其余 7 国；受影响会话 resume 即恢复，transcript 从存档恢复
- 无事件时段零 LLM 调用（成本审计可证）；无事件时段零常驻子进程（按需 resume 可证）
- 同一国家跨窗口言行与承诺连续（共享内心；引 agent需求 验收"跨窗口一致"）
- 目标编辑与记忆写入均可在 `.history/` 回放留痕
- 关停：排水→落盘→卸载→断开全序完成，无残留子进程与连接；关停后按续局路径重启可恢复对局
