# 集成测试

怎么验证这套东西：局部——每个子模块的集成测试，是测试文件，在 VSCode 里跑；全局——整个系统的集成测试，没有测试文件，是真正把系统跑起来，人去操作、观察过程和结果。

## 集成测试与自动测试的关系

- 集成测试直接打系统外的东西：game 打真游戏、im 打真 Discord、agent 起真 SDK 会话。因此外界前提（游戏在跑、token 填了、代理通、Claude Code 登录了）不满足时它就**失败**——这是设计出来的行为：报错写明缺什么前提，失败说的是"前提没配好"，不是代码坏了
- 命令行全量跑（`uv run pytest`）默认排除集成测试（pyproject 的 addopts 配了 `-m "not integration"`），自动测试不被它们拖红；VSCode 测试面板不受排除影响（.vscode/settings.json 的 pytestArgs 配了 `--override-ini=addopts=`），点哪个跑哪个——面板里能下断点、看输出、单步跟过程
- 单测（`uv run pytest`，面板里同样能点）仍是改完代码的底线：模块行为全验，与系统外的交互用替身（game 读真实格式的样例日志、im 用假 discord client、agent 用假会话）。替身的边界：与系统外模块的交互在集成测试里不造假——game 的集成测试读真 error.log（游戏得开着）、im 的集成测试收发真 Discord 消息；agent 的会话本体单测用假会话（FakeSession）是可接受的，agent 的集成测试只把工具换成假的、会话是真的

## 局部：子模块的集成测试

都在 VSCode 测试面板里点跑（测试树按文件分组，文件路径如下）。

### game——三大操作（get_state、start_play、new_year）

文件：[test/game/test_integration.py](../../test/game/test_integration.py)

前提：Victoria 3 在跑（[运行](运行.md)每次启动第 2 步）。游戏没跑时：前两个测试立即失败，报"游戏未在跑：进程表里没有 victoria3.exe"；第三个白等几分钟后失败。

- **test_get_state_reads_real_world_snapshot**：调 get_state，控制台打印列强快照（16 国的名次/GDP/军力）＋大不列颠财政（金库/债务本金/周净收支）——数字对得上游戏内即过
- **test_start_play_returns_fixed_not_implemented_response**：调 start_play，写侧占位，返回"未实现"应答即过
- **test_new_year_event_arrives_when_game_year_advances**：起主体的年度节拍＋事件总线，收到 new_year 事件即过。error.log 已有本局记录时首轮几秒内就推（把已察觉的当前年份推出来）；新开一局第一年（日志还没有本局记录）要等游戏跑完当年——默认等 5 分钟，环境变量 INTEGRATION_NEW_YEAR_WAIT_SECONDS 可调长

### im——gbr bot 收发读＋dm bot 命令

文件：[test/im/test_im_integration.py](../../test/im/test_im_integration.py)

前提：config.toml 填好两个 token 与 player_id（私信发给 player_id 这位玩家）、代理通 Discord（[运行](运行.md)每次启动第 1 步）。token 没填：立即失败，报缺哪项。

- **test_send_message_给人发私信discord上收得到**：起两个真 bot，给玩家发一条私信——Discord 上收到 gbr bot 的私信即过
- **test_收命令与私信后回话discord上看得到**：起两个真 bot 后等人操作（限时 300 秒）——公屏 @ dm bot 下一条命令（开始游戏/保存游戏/结束游戏任一）、给 gbr bot 发一条私信；两头都收到后测试回话，公屏看到回执、私信看到回复即过

### agent——收 message、收 new_year、调工具

真会话的文件：[test/agent/test_agent_integration.py](../../test/agent/test_agent_integration.py)（前提：config.toml 配了模型凭证三项走它，或本机 Claude Code 已登录——两者其一）

- **test_真会话送批收回复并续上下文**：真 SDK 会话起会话，开局批真的送进会话（读 profile、亮相），四件工具换成假的（send_message 只记录不真发）。通过标准：控制台打印出会话发出的亮相消息、gbr 的 profile 长出来。工具背后的 game、im 由各自的集成测试验；四件工具全真的循环走全局

假会话的单测：[test/agent/test_agent_module.py](../../test/agent/test_agent_module.py)——消息队列的攒与送（空闲即送、忙时攒批合并）、私信落盘、gbr 重建装 profile、收尾整理批、局外丢弃、会话已在跑报错。改 agent 代码跑它。

### 主体

装配与调度（命令分流、频道挡板、收尾顺序）单测盖住（[test/test_dispatcher.py](../../test/test_dispatcher.py)、[test/test_main.py](../../test/test_main.py)）；它的集成验证走下面的全局。

## 全局：整个系统的集成测试

不是测试文件——被测的就是运行中的系统。照[运行](运行.md)每次启动把游戏与 harness 跑起来，人在 Discord 与游戏里操作，观察三处的过程和结果：Discord 界面、harness 终端日志、gbr 文件夹。从头到尾一局，每步做什么、看到什么算对：

1. 开游戏：launcher（GreatBritainAgent playset）开一局单机新游戏，选自己的国家（非大不列颠），跑起来
2. 起 harness：日志出现"dm bot 已登录 Discord""gbr bot 已登录 Discord"
3. 开局：大厅频道 @ dm bot 下"开始游戏"——公屏落回执"开始游戏 执行完成"、服务器出现 GreatBritain 频道、日志出"建了全新的 gbr"；随后 gbr bot 私信发来亮相（他是谁、这局想干什么）。这一步验的是：命令通道收命令、建频道、建 gbr、起会话、agent 调发消息工具。频道已在（上次局没结束游戏）会被拒绝，先下"结束游戏"收掉再开始
4. 对话：给 gbr bot 发私信——日志出"gbr bot 收到私信"、gbr/world/chat/dialogue.jsonl 落一条、会话被唤醒后 gbr bot 回话。验：message 事件的整条链（进队列、落盘、唤醒会话）与私信一进一出
5. 问世界：私信问他"现在列强都是什么家底"——他调 get_state（真工具打真游戏），回话里带真实的 GDP/军力/自家财政数字。验：get_state 接进会话
6. 发博弈：让他对某国发起外交博弈——他调 start_play，现在返回"未实现"应答、他如实转告。验：start_play 接进会话（写侧占位返回占位应答，行为是对的）
7. 过年：游戏速度拉满跑过年末——日志出"游戏进入 XXXX 年，推 new_year 事件"、会话被新年唤醒、gbr bot 私信发来年度研判（gbr/memory/ 里通常也有研判底稿）。验：新年判定节拍 → new_year 事件 → 会话的整条链
8. 翻旧账：问他"我们之前聊过什么"——他调 read_message 翻私信记录（或读 world/chat/dialogue.jsonl），回话接得上前文。验：读的能力
9. 保存：大厅频道 @ dm bot 下"保存游戏"——会话收尾批整理 memory 后结束、GreatBritain 频道留着、公屏落回执"保存游戏 执行完成"
10. 复盘：gbr 文件夹看一局的痕迹——memory/ 的账本与年度研判、world/chat/dialogue.jsonl 的完整对话（结束游戏后清空，要看趁现在）
11. 结束：@ dm bot 下"结束游戏"——频道销掉、gbr 清空，这局彻底完；再开新局回第 3 步
