# agent-记忆和人格

agent 的设计分两块，本文件写记忆与人格：会话活着不等于玩得对——玩一整局，靠的是开局带进场的设定与盘上的账本，让他在整局里记得自己是谁、玩得连贯。会话怎么跑起来（gbr 文件夹、工具、消息队列、会话起止）见 [agent-运行时](agent-运行时.md)。

人格与玩法分三层装载，各管各的：

- **system prompt**——开发文件夹 prompt/ 下的 agent-system-prompt.md，固定内容，起会话时注入（完全替换 SDK 默认的 system prompt——agent 是玩家，不吃助手默认人设）：你是谁、文件夹世界怎么用、被叫醒的节律、说话的规则、"你只知道你查的"认知模型
- **gbr-template/**——开发文件夹 prompt/ 下的 agent 工作空间模板，开始新游戏时整个复制成全新的 gbr：CLAUDE.md 是大不列颠玩家手册（开局流程、年度循环、账本、怎么和玩家处），会话启动时由 SDK 作为项目指令自动装载；账本 md（历史记录、外交计划、外交状态、玩家对应）平铺在模板根下
- **账本 md——agent 唯一可写**：历史记录（大事记与年度研判，逐条追加）、外交计划（本局方针，初始为固定版本）、外交状态（实际与计划的核对）、玩家对应（Discord ID 与国家表）；历年的世界格局也由 agent 自己逐年记在账本里。往后要长新文件就往 gbr-template 里加

与玩家的对话不落盘：收私信（到达即送进会话）、发私信、翻最近的私信都走 Discord 工具，更早的与要紧的靠 agent 自己记进账本——历史记录记事、外交状态记印象。游戏状态的事实源是 error.log（游戏接入解析）：当下看走 get_state 工具，历年的格局走账本。

一局之内记忆的连续性走文件夹：都在盘上，局挂着的期间一直在（继续游戏重新起会话，账本接着用）；保存并结束游戏把局连同记忆一起收掉，下一局从全新的 gbr 开始。
