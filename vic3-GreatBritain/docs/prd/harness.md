# harness

harness 是整个程序的主体，一个 Python 进程，装四块：主体负责整个程序的生命周期、调用其余三块实现功能；三个子模块各管一摊——游戏接入（game）、agent、IM 接入。三个子模块在本文档只写声明（能力是什么），实现各在自己的文档：游戏接入已实现，见[游戏接入-harness侧](游戏接入-harness侧.md)；IM 接入已实现，见[Discord 接入](discord接入.md)；agent 已实现，见[agent-运行时](agent-运行时.md)。

## 主体

主体是 harness 的骨架，管整个程序的生命周期，三个子模块由它装载、调用。

- 进程与会话：harness 进程不绑局文件夹；agent 会话随局起止——开始游戏起会话（建本局频道与全新的 gbr），保存游戏让会话整理自己的文件夹后结束会话（局还挂着，频道留着），结束游戏会话收尾、销频道、清 gbr，这局彻底完
- 事件队列：主体维护一条事件队列，模块之间互不引用，来往全走它——进队列的动作全在装配处：IM 接入收到命令与消息调主体注册的回调，装配处挂回调时在闭包里包事件推进队列；游戏接入的新年判定由主体定时调、查到新年份主体自己推；订事件也在装配时办，主体自己也订。三种事件：command（玩家命令，IM 接入的命令回调、主体订）、message（玩家消息，IM 接入的消息回调、agent 订）、new_year（年度通知，主体推、agent 订）

## 主体实现

主体是装配加调度的一层，自身没有业务逻辑，实现写在本节、不另起文档。代码在 vic3-GreatBritain/src/（测试在 test/，按模块分目录）：main 管入口与装配，调度模块管分流、局状态与命令执行，三大模块各成一个包（agent、game、im，实现进各包 impl/）。

- 入口与配置：进程从 main 起，读开发文件夹下的 config.toml（模板 config.example.toml）——两个 bot 的 Discord token（dm_token、gbr_token）、error.log 路径、游戏进程名、局文件夹与 gbr 路径、两处运行日志目录（system_log_dir、agent_log_dir——局文件夹下 logs/system 与 logs/agent，随局文件夹派生，config.toml 不填；进程启动时配好系统日志双写，记录内容见[日志功能](日志功能.md)）、agent 会话的模型与凭证三项（anthropic_base_url、anthropic_auth_token、agent_model——配了 agent 会话走它，与玩家自己的 Claude Code 分开）
- 装配：按配置把三大模块建出来、接上——游戏接入是进程内模块，直接实例化；IM 接入挂上命令与消息的回调（闭包里包事件推进队列），再登录 Discord；agent 持会话。模块之间互不引用，谁接谁只有主体知道。主体还干两件接线：会话工具由主体组合——把游戏接入的方法与 IM 接入的收发（读私信历史、发私信，带玩家 ID 参数、agent 调用时自己填，值从收到的私信里学）组合成 agent 会话的工具，装配时递给 agent 模块挂进会话；年度节拍由主体起——定时调游戏接入的新年判定，查到新年份推 new_year 事件。profile 模板源在开发文件夹 profile/，起会话建全新 gbr 时装入
- 事件循环：一个主循环（asyncio），进程活着就在等事件——模块包成事件推进队列，主循环逐个取、按事件类型投给订了它的模块，一次投一个，投递串行
- 局状态与命令执行：主体记一个状态——会话在不在跑；本局频道（GreatBritain）在不在是局挂没挂着的外显（问 IM 接入）。命令到了按状态排动作：开始游戏先看频道——已在就拒绝，没有就建频道、建全新的 gbr 文件夹起 agent 会话（接线已在装配完成：工具装配时递进 agent 模块），永远开新局；保存游戏让会话整理自己的文件夹，然后结束会话，频道留着；结束游戏先看频道——没有就拒绝，有则会话在跑先按保存游戏收尾，然后销频道、清 gbr。主体只排顺序，动作本身调三大模块干。执行完调 IM 接入发回执（固定文案，发到命令来的频道），没执行成（拒绝重复起这类）回执带原因
- 退出：进程收摊，会话还在跑就先按保存游戏收尾再退

## 游戏接入（game）

agent 的眼睛，跑在 harness 进程内：mod 在游戏里每年把世界格局写进 error.log，游戏接入把日志变成三个方法——两个给 agent 调，一个新年判定给主体定时调，主体查到新年份往事件队列推 new_year 事件。声明三个能力：

- get_state——读取世界局势：各国最新一条记录拼成的世界格局快照
- start_play——发起博弈：发起一局外交博弈
- check_new_year——新年判定：查 error.log 是否出现新的本局记录年份，有返回该年份、没有返回 None；主体定时调它，查到新年份往事件队列推一个 new_year 事件（data 为年份数字）

get_state/start_play 以游戏在跑为前提（没跑直接报错）；新年判定在游戏没跑时返回 None。行格式与实现细节见[游戏接入-harness侧](游戏接入-harness侧.md)。

## agent

agent 本体是 Claude Code 会话。局文件夹固定一个：C:\Users\ZhangJunWei\Documents\Paradox Interactive\Victoria 3\vic3-GreatBritain；agent 的记忆文件放在它下面的 gbr 文件夹，profile/world/memory 三区由 agent 管理装载。会话的工具由主体装配时递入（主体把游戏接入的方法与 IM 接入的收发包成会话工具），agent 模块只管挂进会话，不知道工具背后是什么。消息侧的能力已定：

- 消息队列——收（订 message、new_year）：两类到达收进队列，会话空闲即送进会话、唤醒它；会话在忙则攒着，空闲了把攒下的合并成一段上下文送进会话、唤醒它
- 发消息——说：会话里挂的发消息工具，agent 填玩家的 Discord 用户 ID（从收到的私信里学）把话发到他的私信（工具背后是 IM 接入的发送方法）

细化与实现见[agent-运行时](agent-运行时.md)。

## IM 接入

agent 的嘴和耳朵，通 Discord，两个 bot 分工——dm bot 主持命令、gbr bot 是大不列颠玩家的门面（细化与实现见[Discord 接入](discord接入.md)）。收是被动的：bot 在线收着，收到的命令与消息调主体注册的回调交出去（装配处包成事件推进队列，模块零总线知识）；发与读是主动的：主体调模块的发送方法与读取方法，包成 agent 的会话工具（发消息、读消息）。两块能力：

- 命令通道（收命令交回调＋管本局频道）：玩家在大厅频道 @ dm bot 下命令，dm bot 非 LLM 驱动，命令词匹配白名单，命中调命令回调（装配处包成 command 事件推进队列，主体订到后执行）。三条命令：
  - 开始游戏：建本局频道（GreatBritain），初始化 gbr 文件夹，起一个基于它的 agent 会话，接上 IM 和游戏接入；频道已在（上次局没结束）就拒绝
  - 保存游戏：让会话整理自己的文件夹，然后结束会话；频道留着，局还挂着
  - 结束游戏：会话在跑先收尾，然后销毁本局频道、清 gbr 文件夹；没有频道就拒绝
- 对话通道（收消息交回调＋读私信历史＋发私信）：玩家私信 gbr bot——玩家的话调消息回调（带玩家；装配处包成 message 事件推进队列，agent 收进消息队列）；读私信历史与发私信由主体包成 agent 的会话工具（读消息、发消息），工具背后调本模块的读取与发送方法，gbr bot 把话发到玩家私信
