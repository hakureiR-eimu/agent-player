# 日志功能

系统的运行记录落在盘上两处，都在局文件夹（vic3-GreatBritain）的 logs/ 下：system/ 记 harness 进程的运行日志，agent/ 记 agent 会话的运行过程。两处都是开发侧的档案，给人排查与回看用——agent 自己的记忆在 gbr 文件夹（见 [agent](agent.md) 的记忆与人格）。

gbr 随局生灭（结束游戏清掉），logs 跨局累积：局完了记录还要能翻。游戏引擎自己的日志目录是 Victoria 3\logs（error.log 在那里，是 mod 写世界格局的载体），局文件夹的 logs/ 是 harness 自己的。

## 系统日志（logs/system）

全库统一走 Python 的 logging：各模块的 logger 输出都汇到这——模块起停、命令执行、事件流转、新年判定、异常堆栈，INFO 级。每次进程启动建一个新文件，文件名带启动时刻（harness-2026-11-22_15-30-00.log），本次运行写进它；控制台同步输出，双写。

一行一条，格式沿用现有的 `%(asctime)s %(name)s %(levelname)s %(message)s`：

```text
2026-11-22 15:30:01,002 main INFO 游戏进入 1837 年，推 new_year 事件
```

## agent 运行记录（logs/agent）

agent 会话里流过的消息逐条落盘：SDK 的 query 送批期间流式吐消息，流过的按四类记——

- agent 说的话（assistant）——文本正文
- 工具调用（tool_use）——工具名与参数
- 工具结果（tool_result）——SDK 回灌的执行回执
- 批收尾（result）——每批跑完的汇总：会话 id、耗时、轮数、花费

一次会话一个文件：开始游戏起会话时按开局时刻建（agent-2026-11-22_15-31-02.jsonl），整局的各批都追加进它。jsonl 一行一条（`<>` 为占位）：

```json
{"time": <时刻>, "kind": "assistant", "text": <正文>}
{"time": <时刻>, "kind": "tool_use", "tool": <工具名>, "input": <参数>}
{"time": <时刻>, "kind": "tool_result", "text": <回执>}
{"time": <时刻>, "kind": "result", "session_id": <会话id>, "duration_ms": <耗时>, "num_turns": <轮数>, "total_cost_usd": <花费>}
```

与 gbr 的分工：world/chat/dialogue.jsonl 记玩家私信对话，是 agent 的事实记录（他翻旧账用）；这里的全记录含工具调用与结果，是给人的排查档案。

## 实现：怎么做

- 位置：两个目录从局文件夹派生（logs/system、logs/agent），进 Config 字段、config.toml 不新增填写项（同 gbr 的派生方式）
- 系统日志：main 起进程时配 logging 双写——文件 handler（utf-8）写 system 目录＋控制台 handler
- agent 记录：起会话时在 agent 目录建本局记录文件，路径递进会话；SdkSession 送批的消息循环里把流过的消息拆块取内容、逐条追加（jsonl 序列化）
- 测试：单测盖 config 派生与记录文件的建立（起会话建文件、文件名带时刻）；会话内逐条追加走 agent 集成测试（真会话才流消息）
