# 游戏接入-mcp侧

游戏接入拆成两侧：mod 侧（[游戏接入-mod侧](游戏接入-mod侧.md)）把游戏内状态导出到 debug.log，mcp 侧（本文件）把日志变成 agent 可用的工具。mcp-server 在 vic3-GreatBritain/mcp-server/，Python 写，是游戏侧唯一的外部通道。第一版读工具直接实现；写工具只声明一个——发起外交博弈（start_play），实现空置，随写侧版本补。

## 职责与边界

mcp 侧的边界：从 debug.log 到 MCP 工具为止——解析 mod 侧定义的年度记录（行格式与封闭清单见 mod 侧文档，两侧以行格式为交接面），把状态读取包装成标准的 MCP 服务。不读存档（直读已否决，见[存档直读验证](../调研/存档直读验证.md)）。

## 声明：做什么

第一版两个工具：

- get_state：读游戏的最新状态——各国最新一条记录拼成的世界格局快照，返回结构化数据
- start_play：发起外交博弈（写工具），实现空置——工具注册给客户端，调用返回固定的"未实现"应答

## 实现：怎么做

- 日志定位：默认 Documents/Paradox Interactive/Victoria 3/logs/，路径可配置；链路验证不造 mock，配置指向一份真实格式的样例日志即可单测
- 记录识别：逐行扫日志，认行内前缀 `vic3-GreatBritain `（局名前缀，mod 侧定义；行首有游戏加的时间戳/来源头），两类行：`state`（国家行）、`fin`（财政行）；行内 key=value 逐对解析、按字段名取值——year 的值是完整本地化日期（如 `12月 27, 1837`，含空格逗号），从值尾取 4 位数字为年份；数值转数字，行尾 CRLF；字段含义与行格式以 mod 侧文档为准
- 残行：游戏把日志攒在内存里、攒一批才落盘，在跑文件的末行可能只有前半截——解析不出就跳过，下次读它就完整了
- 去重：同一 (tag, year) 后出现的覆盖先出现的——读档重跑同一年，以最新一次为准
- 取数与排序：每国取它最新一条记录（当年还没触发的国家自然落在上一年的记录上），拼成快照；输出前 powers 按 rank 升序排好，rank 是行内触发时点的当刻名次、可能并列；通常 16 国，席位变动时可能 15–17 国
- 无数据：游戏第一年（首次年度导出前）日志里还没有本局记录，get_state 返回空
- MCP 接入：Python＋官方 SDK（mcp，modelcontextprotocol/python-sdk），stdio 传输，客户端按常规 MCP 服务挂载
- get_state 返回模板（`<>` 为占位）：

  ```json
  {
    "powers": [
      { "tag": <tag>, "year": <年>, "rank": <名次>, "gdp": <GDP>, "army": <营队数> }
    ],
    "gbr_finance": { "year": <年>, "gold": <金库>, "debt": <债务本金>, "week_net": <每周净收支> }
  }
  ```

  示例（实测值，国家行为 1837 年、财政行为 1836 年开局——两条年份不同正是"每国取最新一条"的常态；powers 通常 16 国、1837 年 GBR rank=1，此处截短）：

  ```json
  {
    "powers": [
      { "tag": "FRA", "year": 1837, "rank": 3, "gdp": 24109387.47464, "army": 282 }
    ],
    "gbr_finance": { "year": 1836, "gold": 0, "debt": 440232.39442, "week_net": -108278.71675 }
  }
  ```

## 前提

- 存档可在 pdx_settings.json 里设成文本格式，mcp-server 可用它做全量校准
